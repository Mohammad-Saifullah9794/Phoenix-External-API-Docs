# Get Organization

Returns the organization your API key belongs to: its profile details (as entered in the admin panel), how many identities it may create, its storage quota, and which services are enabled.

<ApiEndpoint method="GET" path="/organization/info" auth={true} />

## Permissions

Requires the `organization:view` permission. See [Permissions](../../permissions).

## Headers

| Header | Required | Description |
|--------|----------|-------------|
| `x-api-key` | Yes | Your API key, as a UUID. See [Authentication](../../authentication). |

## Request

No path parameters, query parameters, or request body.

curl --location '<BASE_URL>/organization/info' \
--header 'x-api-key: <API_KEY>'

| Field | Type | Description |
|-------|------|-------------|
| `organization_id` | `string` (UUID) | Your organization's ID |
| `organization_name` | `string` | Organization display name |
| `organization_info` | `object` | Profile details entered in the admin panel. See [`organization_info` fields](#organization_info-fields) below. |
| `is_active` | `boolean` | Whether the organization is active |
| `allocated_email_identities` | `integer` | How many identities the organization may have. `-1` means unlimited. |
| `utilized_email_identities` | `integer` | How many identities exist now. Goes up by 1 on [Create Identity](../identities/create) and down by 1 on [Delete Identity](../identities/delete). When it reaches `allocated_email_identities`, creating identities fails with `403`. |
| `quota_allocated` | `number` | Total mailbox storage allocated to the organization, in GB |
| `quota_utilized` | `number` | Storage already assigned to mailboxes, in GB |
| `chat_service_enabled` | `boolean` | Whether the chat service is enabled |
| `email_service_enabled` | `boolean` | Whether the email service is enabled |
| `file_service_enabled` | `boolean` | Whether the file service is enabled |
| `created_at` | `string` (ISO 8601) | When the organization was created |

#### `organization_info` fields

Every field is optional — an organization created without them returns `{}` or only some of the keys.

| Field | Type | Description |
|-------|------|-------------|
| `type` | `string` | Organization type: `Customer`, `Partner` or `Re-Seller` |
| `description` | `string` | Short description of the organization |
| `website` | `string` | Website URL |
| `gst_number` | `string` | GST registration number |
| `branches` | `object` | Office locations. Each key is a random ID generated by the admin panel; each value is a **Branch** object (below). |
| `contact_info` | `object` | Contact people. Each key is a random ID; each value is a **Contact** object (below). |

**Branch object**

| Field | Type | Description |
|-------|------|-------------|
| `name` | `string` | Branch name, e.g. `Head Office` |
| `address_one` | `string` | Address line 1 |
| `address_two` | `string` | Address line 2 |
| `city` | `string` | City |
| `state` | `string` | State |
| `country` | `string` | Country |
| `pincode` | `string` | Postal code |

**Contact object**

| Field | Type | Description |
|-------|------|-------------|
| `name` | `string` | Contact name |
| `phone` | `string` | Phone number |
| `email` | `string` | Email address |
| `type` | `string` | Role of the contact, as entered in the admin panel |
| `notes` | `string` | Free-text notes |

:::note Read-only
The API can read these details but not change them. Edit them in the admin panel under **Organizations**.
:::

## Errors

| Status | Meaning |
|--------|---------|
| `401` | Missing/invalid `x-api-key`, or missing `organization:view` permission |
| `417` | The organization has been deactivated (currently returned as a database error rather than a clear message) |
